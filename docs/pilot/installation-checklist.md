# Pilot Installation Checklist

Complete this checklist with the hospital pilot lead. Record the owner, date, and evidence for each item. Do not enter real patient information into a test environment.

## Before installation

- [ ] Name the pilot lead, department super-users, support contacts, and escalation route.
- [ ] Confirm the pilot scope, approved workflows, patient volume, data handling terms, and privacy notice with hospital leadership and counsel.
- [ ] Verify hospital Wi-Fi and mobile data coverage in each target department; test the actual staff and patient devices.
- [ ] Confirm device OS versions, app build, backend environment, timezone, locale, and date/time display with the pilot lead.
- [ ] Confirm test and production accounts by role. Verify access is limited to authorized people and remove temporary setup credentials.
- [ ] Configure HMS integration if applicable. Document the interface, data exchanged, test evidence, owner, and manual fallback. If no integration is approved, record “not in scope.”
- [ ] Record baseline metrics (including current wait times) with measurement window, sample size, owner, and source.
- [ ] Agree on the on-call support channel, primary/backup contacts, support hours, and emergency telephone process.

## Install and configure

- [ ] Install and secure tablets at reception and nursing stations; record device owner, location, and asset identifier.
- [ ] Install the approved staff app build on staff phones or tablets. Verify the package came from the approved distribution source.
- [ ] Sign in with a role-appropriate account and confirm that each user sees only the screens/actions assigned to that role.
- [ ] Print patient fliers only after adding the verified Play Store link/QR code, support phone number, and approved privacy wording.
- [ ] Set up one trained super-user per department and confirm who can add, disable, or reset accounts.
- [ ] Check that notification permissions and microphone permission are explained and can be declined without blocking other available workflows.

## End-to-end acceptance checks

- [ ] Test patient registration and OTP delivery using an approved test account and phone.
- [ ] Test voice with the hospital's actual department and doctor names; verify the patient reviews and confirms an appointment proposal before booking.
- [ ] Test appointment and queue status updates with a test patient and staff account; confirm the patient-facing queue updates as expected.
- [ ] Test SOS end-to-end on the hospital network with the emergency team and a designated test account. Verify receipt and the agreed human response. Keep the hospital emergency phone procedure available.
- [ ] Test the feedback flow using a completed test appointment, including rating, NPS response (if enabled), and confirmation that the admin report handles an empty sample honestly.
- [ ] Verify service health and the agreed monitoring/incident escalation route. Record the time and evidence; do not treat a health check as proof that every workflow is healthy.
- [ ] Confirm the manual fallback for each workflow and rehearse who activates it.

## Training and go-live approval

- [ ] Train at least one super-user per department; record attendance and any open questions.
- [ ] Review the staff training material and support runbook with the on-call team.
- [ ] Confirm each checklist item has an owner and evidence, or record a blocker and due date.
- [ ] Obtain written go-live approval from the hospital pilot lead, clinical/safety owner, IT/security contact, and Provider pilot lead.
- [ ] Schedule the first review and confirm baseline data and success measures will be reviewed with sample sizes and known limitations.
